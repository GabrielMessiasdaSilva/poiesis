# Testes k6 do Poiesis

Este guia permite executar os testes a partir da raiz do repositório. Faça isso apenas em ambiente de desenvolvimento ou homologação: os produtos e opções de teste são inativados no final, mas as contas de teste, pedidos, ordens de produção e projeções do relatório permanecem gravados.

## Pré-requisitos

- k6 instalado (`k6 version`)
- Java 21 e Maven
- seis serviços do Poiesis ativos e acessíveis pelo gateway em `http://localhost:8080`
- RabbitMQ ativo e conectado aos serviços
- credenciais válidas de um usuário com perfil de administrador

Se os serviços ainda não estiverem ativos, inicie o RabbitMQ conforme a configuração do seu ambiente e execute `bash poiesis-backend-spring/iniciar-projeto.sh`. O script inicia os serviços nas portas locais; se informar que já existem serviços ativos, não rode o comando de parada sem confirmar que são processos descartáveis.

Defina as credenciais no terminal, sem gravá-las neste arquivo:

```bash
export ADMIN_EMAIL='seu-admin@exemplo.com'
export ADMIN_PASSWORD='sua-senha'
export CLIENT_PASSWORD='senha-de-teste-com-8-ou-mais-caracteres'
```

Os scripts criam uma conta temporária de cliente exclusiva para cada execução e fazem o pedido com essa conta, como no fluxo real. `CLIENT_PASSWORD` precisa ter ao menos oito caracteres.

## Executar os cenários

Rode os comandos abaixo a partir da raiz do repositório:

```bash
k6 run -e BASE_URL=http://localhost:8080 -e VUS=20 -e ITERATIONS=100 -e QUANTIDADE_POR_PEDIDO=3 -e ADMIN_EMAIL="$ADMIN_EMAIL" -e ADMIN_PASSWORD="$ADMIN_PASSWORD" -e CLIENT_PASSWORD="$CLIENT_PASSWORD" poiesis-backend-spring/multi_request/teste-carga.js

k6 run -e BASE_URL=http://localhost:8080 -e VUS=10 -e ITERATIONS=50 -e ADMIN_EMAIL="$ADMIN_EMAIL" -e ADMIN_PASSWORD="$ADMIN_PASSWORD" -e CLIENT_PASSWORD="$CLIENT_PASSWORD" poiesis-backend-spring/multi_request/teste-customizacao.js

k6 run -e BASE_URL=http://localhost:8080 -e VUS=10 -e ADMIN_EMAIL="$ADMIN_EMAIL" -e ADMIN_PASSWORD="$ADMIN_PASSWORD" -e CLIENT_PASSWORD="$CLIENT_PASSWORD" poiesis-backend-spring/multi_request/teste-concorrencia.js
```

`teste-carga.js` cria pedidos em paralelo e confere valores, integridade, IDs únicos e uma ordem de produção por pedido. `teste-customizacao.js` testa operações simultâneas em opções distintas. `teste-concorrencia.js` disputa atualizações dos mesmos registros e confere o estado final e a propagação do status do pedido ao cliente; cada VU executa uma disputa em lote.

Para guardar o resumo de cada execução, acrescente `--summary-export=resultado-k6.json` ao comando. Use um nome diferente para cada cenário se quiser manter os três resultados.

## Encerrar

Depois dos testes, encerre os serviços somente se foram iniciados por você para esta execução. Na raiz:

```bash
bash poiesis-backend-spring/iniciar-projeto.sh parar
```

O k6 falha se qualquer check não passar ou se houver resposta HTTP inesperada. Os resultados representam apenas a configuração e a quantidade de VUs executadas; não são uma estimativa automática de capacidade de produção ou de SLA.
